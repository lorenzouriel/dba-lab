3 — Initialize Databases
5

Build & Deploy Schema via dacpac

PowerShell 
.\dba-lab.ps1 init

This runs scripts\init\init-all.ps1 which, for each of the 4 containers:

  • Waits for SQL Server to become ready
  • Builds db.sqlproj via MSBuild → produces .dacpac artifact
  • Publishes AppDB dacpac via SqlPackage /Action:Publish — creates database if needed, diffs schema, applies delta
  • Verifies deployed objects (tables, procedures, views)
No hardcoded object lists. All tables, procedures, views, and post-deployment scripts are defined in the .sqlproj files. Add a new .sql file to the project and it deploys automatically — no script changes needed.

4 — Configure Availability Group
This is the core HA step. It creates a two-node Always On AG between sql-prod-1 (primary) and sql-prod-2 (secondary) using certificate-based authentication — no Active Directory required.
6

Run the AG Setup

PowerShell 
.\dba-lab.ps1 ag

This orchestrates 6 internal steps:

What Happens Under the Hood

#StepNodeWhat It Does
1Verify HADRBothChecks SERVERPROPERTY('IsHadrEnabled') = 1
2FULL Recoveryprod-1ALTER DATABASE [AppDB] SET RECOVERY FULL
3Full Backupprod-1Backup to shared volume: /var/opt/mssql/shared/AppDB_full.bak
4Configure Primaryprod-1Master key → Certificate → Backup cert to shared volume → Endpoint (5022) → Create AG
5Configure Secondaryprod-2Master key → Restore cert from shared volume → Endpoint (5022) → Join AG
6Automatic SeedingBothAG automatically replicates AppDB to secondary (~10s wait)

AG Configuration Details

CREATE AVAILABILITY GROUP [AppDB_AG]
WITH (
    CLUSTER_TYPE = NONE,       -- No WSFC needed (Docker)
    DB_FAILOVER = ON
)
FOR DATABASE [AppDB]
REPLICA ON
    N'sql-prod-1' WITH (
        ENDPOINT_URL       = N'TCP://sql-prod-1:5022',
        AVAILABILITY_MODE  = SYNCHRONOUS_COMMIT,
        FAILOVER_MODE      = MANUAL,
        SEEDING_MODE       = AUTOMATIC,
        SECONDARY_ROLE (ALLOW_CONNECTIONS = ALL)
    ),
    N'sql-prod-2' WITH (
        ENDPOINT_URL       = N'TCP://sql-prod-2:5022',
        AVAILABILITY_MODE  = SYNCHRONOUS_COMMIT,
        FAILOVER_MODE      = MANUAL,
        SEEDING_MODE       = AUTOMATIC,
        SECONDARY_ROLE (ALLOW_CONNECTIONS = READ_ONLY)
    );

6 — Test Failover
10

Failover to Secondary

PowerShell 
# Check current state first
.\dba-lab.ps1 status

# Execute failover: sql-prod-1 → sql-prod-2
.\dba-lab.ps1 failover

This runs ALTER AVAILABILITY GROUP [AppDB_AG] FORCE_FAILOVER_ALLOW_DATA_LOSS on sql-prod-2, promoting it to primary.

CLUSTER_TYPE=NONE requires manual failover. In production with WSFC or Pacemaker, failover would be automatic. This lab uses manual failover to match the controlled deployment model.

After Failover

  • sql-prod-2 is now PRIMARY (read-write)
  • sql-prod-1 needs to rejoin as secondary
  • To resume sync: restart sql-prod-1 container, then set role to SECONDARY

8 — Build dacpac from SSDT
Why dacpac? A .dacpac is a compiled snapshot of your database schema. When you publish it, sqlpackage compares it against the target database and generates only the delta — CREATE, ALTER, or DROP as needed. No manual scripting, no “object already exists” errors.

16

Test Locally with sqlpackage

Verify the dacpac publishes correctly against your Docker instances:

PowerShell 
# Publish AppDB to Dev
sqlpackage /Action:Publish `
    /SourceFile:db\bin\Release\db.dacpac `
    /TargetServerName:"localhost,1401" `
    /TargetDatabaseName:AppDB `
    /TargetUser:sa `
    /TargetPassword:$env:SA_PASSWORD `
    /TargetTrustServerCertificate:True `
    /p:BlockOnPossibleDataLoss=True
Idempotent. Run this as many times as you want. If schema matches, sqlpackage reports “no actions performed.” If you changed a column type, it generates the ALTER. This is the real power over raw SQL scripts.

Preview Changes Without Applying

Generate the diff script without touching the database:

PowerShell 
# Script only (no publish)
sqlpackage /Action:Script `
    /SourceFile:db\bin\Release\db.dacpac `
    /TargetServerName:"localhost,1401" `
    /TargetDatabaseName:AppDB `
    /TargetUser:sa `
    /TargetPassword:$env:SA_PASSWORD `
    /TargetTrustServerCertificate:True `
    /OutputPath:diff_preview.sql `
    /p:BlockOnPossibleDataLoss=True

Open diff_preview.sql to review exactly what sqlpackage will do.
