# Subqueries vs CTEs: The Answer Everyone Gets Wrong

*Series 2 — Query Mastery | The SQL Server Deep Dive*

---

"Should I use a CTE or a subquery here?" is one of those questions that comes up constantly and gets answered confidently but wrong. The usual answer — "CTEs are for readability, subqueries are for performance" — is an oversimplification that leads to bad decisions.

The real answer depends on what your query actually needs to do, how many times you're referencing the intermediate result, and who's going to maintain this code next week.

---

## What a Subquery Is

A subquery is a SELECT statement nested inside another SELECT statement. The inner SELECT produces a result that the outer SELECT uses — as a filter, as a data source, as a calculated value, or as an existence check.

The nested structure is the defining feature: you can spot a subquery when you see a `SELECT` inside parentheses somewhere other than the top level.

---

## Where Subqueries Can Live

Subqueries appear in five different positions, and each position serves a different purpose.

**In the SELECT clause — correlated scalar subquery**

Returns a single value per row. The inner query references a column from the outer query (that's what makes it "correlated").

```sql
-- Get each product's name with a count of how many times it's been ordered
SELECT
    p.product_id,
    p.product_name,
    p.unit_price,
    (
        SELECT COUNT(*)
        FROM dbo.OrderDetails AS od
        WHERE od.product_id = p.product_id
    ) AS times_ordered
FROM dbo.Products AS p;
```

**In the FROM clause — derived table (inline view)**

The subquery acts as a virtual table. This is the pattern most similar to a CTE.

```sql
-- Order totals per customer, then join back to Customers
SELECT
    c.first_name,
    c.last_name,
    order_summary.total_orders,
    order_summary.total_value
FROM dbo.Customers AS c
INNER JOIN (
    SELECT
        o.customer_id,
        COUNT(*) AS total_orders,
        SUM(od.quantity * od.unit_price) AS total_value
    FROM dbo.Orders AS o
    INNER JOIN dbo.OrderDetails AS od ON o.order_id = od.order_id
    GROUP BY o.customer_id
) AS order_summary ON c.customer_id = order_summary.customer_id;
```

**In the WHERE clause with IN**

Filters rows based on whether a column value appears in the subquery's result.

```sql
-- Orders for products in the 'Electronics' category
SELECT
    o.order_id,
    o.order_date,
    o.status
FROM dbo.Orders AS o
INNER JOIN dbo.OrderDetails AS od ON o.order_id = od.order_id
WHERE od.product_id IN (
    SELECT product_id
    FROM dbo.Products
    WHERE category = 'Electronics'
);
```

**In the HAVING clause**

Filters groups after aggregation using a subquery result.

```sql
-- Products with above-average order frequency
SELECT
    od.product_id,
    COUNT(*) AS order_count
FROM dbo.OrderDetails AS od
GROUP BY od.product_id
HAVING COUNT(*) > (
    SELECT AVG(product_count)
    FROM (
        SELECT COUNT(*) AS product_count
        FROM dbo.OrderDetails
        GROUP BY product_id
    ) AS product_averages
);
```

**In the WHERE clause with EXISTS**

Checks for the existence of matching rows without returning them. Stops as soon as one match is found — often faster than IN for large sets.

```sql
-- Customers who have at least one completed order
SELECT
    c.customer_id,
    c.first_name,
    c.email
FROM dbo.Customers AS c
WHERE EXISTS (
    SELECT 1
    FROM dbo.Orders AS o
    WHERE o.customer_id = c.customer_id
      AND o.status = 'Completed'
);
```

## Subquery vs CTE: The Honest Comparison

The same "completed orders per customer" logic written both ways:

**As a subquery (FROM clause):**

```sql
SELECT
    c.first_name,
    c.last_name,
    order_totals.total_value
FROM dbo.Customers AS c
INNER JOIN (
    SELECT
        o.customer_id,
        SUM(od.quantity * od.unit_price) AS total_value
    FROM dbo.Orders AS o
    INNER JOIN dbo.OrderDetails AS od ON o.order_id = od.order_id
    WHERE o.status = 'Completed'
    GROUP BY o.customer_id
) AS order_totals ON c.customer_id = order_totals.customer_id
WHERE order_totals.total_value > 500;
```

**As a CTE:**

```sql
WITH completed_order_totals AS (
    SELECT
        o.customer_id,
        SUM(od.quantity * od.unit_price) AS total_value
    FROM dbo.Orders AS o
    INNER JOIN dbo.OrderDetails AS od ON o.order_id = od.order_id
    WHERE o.status = 'Completed'
    GROUP BY o.customer_id
)
SELECT
    c.first_name,
    c.last_name,
    cot.total_value
FROM dbo.Customers AS c
INNER JOIN completed_order_totals AS cot ON c.customer_id = cot.customer_id
WHERE cot.total_value > 500;
```

Both produce the same execution plan in most cases. SQL Server's optimizer sees through both and makes the same access decisions. The CTE version is easier to read, easier to debug, and easier to modify.

## When to Choose Each

**Use CTEs when:**
- The logic is complex enough to benefit from a name
- You need to reference the intermediate result more than once in the same query
- You need a recursive query (subqueries can't recurse)
- Someone else needs to understand or maintain this code

**Use subqueries when:**
- The logic is simple and won't be reused
- You're in the SELECT or HAVING clause (scalar or aggregated), where CTEs can't appear
- You need `EXISTS` or `NOT EXISTS` (these are inherently subquery patterns)
- You're writing a quick ad-hoc query that doesn't need to be readable long-term

The most common practical rule: if you're writing a FROM-clause subquery longer than 5–6 lines, strongly consider a CTE instead. The readability gain is almost always worth it.

---

## The Trap

**Duplicating logic instead of choosing one approach cleanly.** The most common error isn't choosing between CTEs and subqueries — it's writing the same subquery twice in the same query because you didn't realize a CTE could be referenced multiple times.

```sql
-- BAD: same subquery written twice
SELECT
    c.first_name,
    c.last_name
FROM dbo.Customers AS c
WHERE (SELECT COUNT(*) FROM dbo.Orders o WHERE o.customer_id = c.customer_id) > 3
  AND (SELECT COUNT(*) FROM dbo.Orders o WHERE o.customer_id = c.customer_id) < 10;

-- GOOD: write the logic once in a CTE, reference it twice
WITH order_counts AS (
    SELECT
        customer_id,
        COUNT(*) AS order_count
    FROM dbo.Orders
    GROUP BY customer_id
)
SELECT
    c.first_name,
    c.last_name
FROM dbo.Customers AS c
INNER JOIN order_counts AS oc ON c.customer_id = oc.customer_id
WHERE oc.order_count > 3
  AND oc.order_count < 10;
```

The CTE version computes `order_count` once. The subquery version computes it twice per row, for every row in `Customers`.

---

## Key Takeaways

- **Subqueries nest inside other queries** — they appear in SELECT, FROM, WHERE, HAVING, and with EXISTS
- **EXISTS stops at the first match** — often faster than IN for large sets; use it when you only need to check for existence
- **FROM-clause subqueries and CTEs are functionally equivalent** — SQL Server generates similar execution plans for both
- **CTEs win on readability and reusability** — they name the result, can be referenced multiple times, and can recurse
- **Subqueries win for EXISTS, SELECT-clause scalars, and one-liners** — these positions don't have a CTE equivalent
- **Never duplicate a subquery twice** — if you reference the same logic more than once, that's the clearest signal to use a CTE
