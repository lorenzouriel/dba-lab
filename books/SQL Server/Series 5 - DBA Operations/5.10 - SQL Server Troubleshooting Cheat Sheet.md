# SQL Server Troubleshooting Cheat Sheet
### Identify → Measure → Resolve. The incident reference card.

Built for speed during a live problem. Terse on purpose — the deep treatment lives in the monitoring/performance, CPU, and HA/DR guides; this is the thing you keep open at 2 a.m.

**The loop, every time:**
- Identify the bottleneck by **waits**
- Confirm it's **systemic vs. one query**
- Measure **how bad** (breadth + duration)
- Fix the **cause** — usually *read less work*, not *add hardware*
- Re-measure that the **waits actually moved**

## STEP 1 — IDENTIFY
### 1a. First 60 seconds — run these in order

**What's happening right now** (native activity snapshot — sort by CPU / elapsed / wait / reads)
```sql
select
    r.session_id, r.status, r.blocking_session_id, r.wait_type,
    r.wait_time / 1000.0 as wait_s, r.cpu_time,
    r.total_elapsed_time / 1000.0 as elapsed_s, r.logical_reads,
    r.open_transaction_count, r.dop, db_name(r.database_id) as db, r.command,
    s.login_name, s.host_name, s.program_name,
    substring(t.text, (r.statement_start_offset / 2) + 1,
        ((case r.statement_end_offset when -1 then datalength(t.text)
          else r.statement_end_offset end - r.statement_start_offset) / 2) + 1) as running_statement,
    qp.query_plan
from sys.dm_exec_requests as r
inner join sys.dm_exec_sessions as s on r.session_id = s.session_id
outer apply sys.dm_exec_sql_text(r.sql_handle) as t
outer apply sys.dm_exec_query_plan(r.plan_handle) as qp
where r.session_id <> @@spid
    and s.is_user_process = 1
order by r.cpu_time desc;       -- swap to: total_elapsed_time / wait_time / logical_reads
```

**Top waits since restart** (the bottleneck fingerprint — diff over a window for a true "now" picture)
```sql
select top (10)
    wait_type, wait_time_ms, signal_wait_time_ms, waiting_tasks_count,
    cast(100.0 * wait_time_ms / sum(wait_time_ms) over () as decimal(5,2)) as pct
from sys.dm_os_wait_stats
where waiting_tasks_count > 0
    and wait_type not in (
        'SLEEP_TASK', 'LAZYWRITER_SLEEP', 'WAITFOR', 'XE_TIMER_EVENT',
        'BROKER_TASK_STOP', 'DIRTY_PAGE_POLL', 'SP_SERVER_DIAGNOSTICS_SLEEP',
        'HADR_FILESTREAM_IOMGR_IOCOMPLETION', 'QDS_PERSIST_TASK_MAIN_LOOP_SLEEP',
        'QDS_ASYNC_QUEUE', 'REQUEST_FOR_DEADLOCK_SEARCH', 'XE_DISPATCHER_WAIT',
        'CXCONSUMER', 'SQLTRACE_INCREMENTAL_FLUSH_SLEEP', 'DISPATCHER_QUEUE_SEMAPHORE'
    )
order by wait_time_ms desc;
```

**One query or systemic?** (active vs. blocked counts)
```sql
select
    count(*) as active,
    sum(case when blocking_session_id <> 0 then 1 else 0 end) as blocked
from sys.dm_exec_requests
where session_id > 50;
```

**Lead blockers** (block others but aren't blocked themselves — replaces `@find_block_leaders`)
```sql
select
    r.blocking_session_id as lead_blocker,
    count(*) as sessions_blocked,
    max(r.wait_time) / 1000.0 as max_block_s
from sys.dm_exec_requests as r
where r.blocking_session_id <> 0
    and r.blocking_session_id not in (
        select session_id from sys.dm_exec_requests where blocking_session_id <> 0
    )
group by r.blocking_session_id
order by sessions_blocked desc;
```

**Idle lead blocker** (open transaction, now sleeping — won't show in ; look up its *last* statement)
```sql
select
    c.session_id, s.open_transaction_count, s.last_request_end_time, t.text as last_statement
from sys.dm_exec_connections as c
inner join sys.dm_exec_sessions as s on c.session_id = s.session_id
outer apply sys.dm_exec_sql_text(c.most_recent_sql_handle) as t
where c.session_id = <lead_blocker_id>;
```

### 1b. The master key — wait type → subsystem
| Top wait | It's a... problem | Section |
|---|---|---|
| `PAGEIOLATCH_*` | **Disk I/O** (or memory forcing re-reads) | I/O / Memory |
| `WRITELOG` | **Disk I/O** — log latency | I/O |
| `RESOURCE_SEMAPHORE` | **Memory** — grant starvation | Memory |
| `RESOURCE_SEMAPHORE_QUERY_COMPILE` | **Memory** — compile gate | Memory |
| `SOS_SCHEDULER_YIELD` (+ runnable queue) | **CPU** pressure | CPU |
| `SOS_SCHEDULER_YIELD` (no queue, huge spins) | **CPU** — spinlocks | CPU |
| `CXPACKET` | **Parallelism** (often a missing index) | Parallelism |
| `LCK_M_*` | **Blocking / locking** | Blocking |
| `PAGELATCH_*` on `2:x:x` | **tempdb** allocation contention | tempdb |
| `PAGELATCH_*` (non-tempdb) | Hot-page contention (last-page insert) | Blocking |
| `THREADPOOL` | **Worker starvation** — usually severe blocking | Blocking |
| `ASYNC_NETWORK_IO` | **Client/network** — app not consuming rows | Network |
| `HADR_SYNC_COMMIT` | **HA** — sync replica latency | (HA/DR guide) |
| `BACKUPIO` / `BACKUPBUFFER` | Backup throughput | I/O |

### 1c. Decision fork
- **Systemic** (many sessions, same wait) → fix the **subsystem**
- **One fat query**, others fine → fix the **query** (plan, index, stats)
- **Blocking chain** → chase the **lead blocker**

## STEP 2 — MEASURE THE IMPACT
Quantify before you act — it sets priority and proves the fix.

**Overall severity** (active/blocked counts, longest wait, longest-running query)
```sql
select
    count(*) as active_requests,
    sum(case when blocking_session_id <> 0 then 1 else 0 end) as blocked_requests,
    max(wait_time) / 1000.0 as max_wait_s,
    max(total_elapsed_time) / 1000.0 as longest_running_s
from sys.dm_exec_requests
where session_id > 50;
```

**Blocking impact** (which blocker is holding up the most sessions)
```sql
select
    r.blocking_session_id,
    count(*) as sessions_blocked,
    max(r.wait_time) / 1000.0 as max_block_s
from sys.dm_exec_requests as r
where r.blocking_session_id <> 0
group by r.blocking_session_id
order by sessions_blocked desc;
```

### What to assess
| Dimension | Question | Where |
|---|---|---|
| **Breadth** | One session or hundreds? | `active` / `blocked` counts above |
| **Duration** | Seconds or growing unbounded? | `max_wait_s`, `longest_running_s` |
| **Scope** | One DB or instance-wide? | group `dm_exec_requests` by `database_id` |
| **vs. baseline** | Is this *abnormal* for now? | compare to Grafana / Query Store history |
| **Business** | Critical app or a stray report? | `program_name` / `login_name` in `dm_exec_sessions` |

### Severity call
- **Act now** (kill / mitigate): growing blocked count + unbounded waits on a production app
- **Diagnose calmly**: bounded, one report, off-hours
- ⚠ **Before killing anything**, know the rollback cost — a kill on a huge open transaction triggers an uninterruptible, possibly *longer*, rollback

## STEP 3 — DEALING WITH EACH SUBSYSTEM
Each subsystem follows the same shape: **Tell → Diagnose → Causes → Fix.**

### MEMORY

- **Tell:** `RESOURCE_SEMAPHORE` waits · memory grants pending > 0 · low/erratic Page Life Expectancy · spills to tempdb

**Diagnose — pending grants + PLE:**
```sql
select count(*) as grants_pending
from sys.dm_exec_query_memory_grants
where grant_time is null;

select object_name, cntr_value as ple_seconds
from sys.dm_os_performance_counters
where counter_name = 'Page life expectancy'
    and object_name like '%Buffer Node%';
```

**Diagnose — who's hogging grants:**
```sql
select session_id, requested_memory_kb, granted_memory_kb, used_memory_kb, dop
from sys.dm_exec_query_memory_grants
order by requested_memory_kb desc;
```

- **Causes:** oversized grants from bad cardinality estimates (granted ≫ used) · `max server memory` unset/too high (starves OS) or too low · plan-cache bloat eating the buffer pool · a few huge queries monopolizing grants
- **Fix:**
  - Right-size grants by fixing estimates (update stats, sargable predicates) — bigger lever than adding RAM
  - Set `max server memory` sanely (leave OS headroom)
  - Enable `optimize for ad hoc workloads`
  - On 2017+, Memory Grant Feedback self-corrects across runs
  - Grants-pending > 0 *sustained* = real memory pressure

### CPU
- **Tell:** `SOS_SCHEDULER_YIELD` · signal-wait % > 15–20% · `runnable_tasks_count` > 0 sustained

**Diagnose — is it SQL or another process?** (SQL vs. idle CPU %)
```sql
declare @t bigint = (select cpu_ticks / (cpu_ticks / ms_ticks) from sys.dm_os_sys_info);

select top (5)
    dateadd(ms, -1 * (@t - [timestamp]), getdate()) as event_time,
    record.value('(./Record/SchedulerMonitorEvent/SystemHealth/ProcessUtilization)[1]', 'int') as sql_cpu_pct,
    record.value('(./Record/SchedulerMonitorEvent/SystemHealth/SystemIdle)[1]', 'int') as idle_pct
from (
    select [timestamp], convert(xml, record) as record
    from sys.dm_os_ring_buffers
    where ring_buffer_type = 'RING_BUFFER_SCHEDULER_MONITOR'
        and record like '%<SystemHealth>%'
) as x
order by [timestamp] desc;
```

**Diagnose — runnable queue depth:**
```sql
select sum(runnable_tasks_count) as runnable
from sys.dm_os_schedulers
where status = 'VISIBLE ONLINE';
```

**Diagnose — top live CPU consumer:**
```sql
select top (5) r.session_id, r.cpu_time, r.dop, t.text as statement_text
from sys.dm_exec_requests as r
inner join sys.dm_exec_sessions as s on r.session_id = s.session_id
outer apply sys.dm_exec_sql_text(r.sql_handle) as t
where s.is_user_process = 1
    and r.session_id <> @@spid
order by r.cpu_time desc;
```

- **Causes:** missing index → scan · stale stats → bad plan · parameter sniffing · implicit conversions · compilation churn (ad-hoc SQL) · over-parallelism · scalar UDFs (pre-2019)
- **Fix:**
  - **Silent taxes FIRST:** power plan → High Performance (`powercfg /getactivescheme`); rule out VM CPU-ready contention
  - Then: add the index, update stats, fix sniffing, raise cost threshold (5 → 50) + set MAXDOP
  - ⚠ `SOS_SCHEDULER_YIELD` with **no** runnable queue = spinlocks (`sys.dm_os_spinlock_stats`), *not* classic CPU

### DISK I/O
- **Tell:** `PAGEIOLATCH_*` (data) · `WRITELOG` (log) · `BACKUPIO`

**Diagnose — per-file read/write latency:**
```sql
select
    db_name(vfs.database_id) as db, mf.name, mf.type_desc,
    case when num_of_reads = 0 then 0 else io_stall_read_ms / num_of_reads end as avg_read_ms,
    case when num_of_writes = 0 then 0 else io_stall_write_ms / num_of_writes end as avg_write_ms
from sys.dm_io_virtual_file_stats(null, null) as vfs
inner join sys.master_files as mf
    on vfs.database_id = mf.database_id
    and vfs.file_id = mf.file_id
order by (io_stall_read_ms + io_stall_write_ms) desc;
```

- **Thresholds:** data files < 10–20 ms/read healthy, > 50 ms bad · log files < 5 ms/write (log is synchronous on commit)
- **Causes (rule out cheap ones first):**
  - *Memory pressure* re-reading evicted pages (looks like I/O — add RAM)
  - Missing index → scan reading 1000× the pages
  - Implicit conversions forcing scans
  - *Then* genuinely slow storage
  - `WRITELOG`: log disk latency, or too many tiny commits (batch them)
- **Fix:**
  - Read less (index, sargability) before buying faster disk
  - Grant **Perform Volume Maintenance Tasks** for instant file init
  - Separate log onto low-latency storage
  - Check autogrowth (frequent small growths = stalls)

### BLOCKING / LOCKING
- **Tell:** `LCK_M_*` waits · blocked count climbing · sessions stuck behind one leader

**Diagnose — the chain + blocked statements:**
```sql
select
    r.session_id, r.blocking_session_id, r.wait_type,
    r.wait_time / 1000.0 as wait_s, r.wait_resource, t.text as blocked_stmt
from sys.dm_exec_requests as r
cross apply sys.dm_exec_sql_text(r.sql_handle) as t
where r.blocking_session_id <> 0;
```

**Diagnose — idle blocker holding an open transaction (classic):**
```sql
select s.session_id, s.login_name, s.host_name, s.open_transaction_count, s.last_request_end_time
from sys.dm_exec_sessions as s
where s.open_transaction_count > 0
    and s.status = 'sleeping'
    and s.is_user_process = 1;
```

- **Causes:** long transaction · idle session left in a transaction (app/SSMS) · missing index forcing broad-lock scans · unindexed FK · wrong isolation level
- **Fix:**
  - **Now:** identify the lead blocker; if it's a stuck/idle transaction, `kill <id>` (know the rollback cost)
  - **Structural:** shorten transactions, add the missing index, consider **RCSI** (readers stop blocking writers — cost: tempdb version store)
  - `THREADPOOL` wait = blocking so severe it's exhausting workers → clear the lead blocker fast

### tempdb
- **Tell:** `PAGELATCH_*` (latch, **not** PAGEIO) on pages like `2:1:1`, `2:1:3` · tempdb full

**Diagnose — allocation contention** (db_id 2 = tempdb):
```sql
select session_id, wait_type, resource_description
from sys.dm_os_waiting_tasks
where wait_type like 'PAGELATCH%'
    and resource_description like '2:%';
```

**Diagnose — space hog:**
```sql
select session_id, user_objects_alloc_page_count, internal_objects_alloc_page_count
from sys.dm_db_session_space_usage
order by (user_objects_alloc_page_count + internal_objects_alloc_page_count) desc;
```

- **Causes:**
  - Allocation contention (many sessions creating temp objects)
  - Space blowout from spills (`internal_objects` ballooning → fix query estimates)
  - Version-store buildup (long-open RCSI/snapshot transaction → find & kill it)
- **Fix:**
  - **Multiple equal-sized data files** (4, or 1/core up to 8); TF 1117/1118 are default behavior on 2016+, don't set them
  - Chase the spilling query or the long transaction

### PARALLELISM
- **Tell:** `CXPACKET` high · small queries running parallel · CPU spread wide
- **Causes:** `cost threshold for parallelism` still at default **5** (trivial queries parallelize) · MAXDOP 0 (one query eats all cores) · **often a missing index** turning a seek into a parallel scan
- **Fix:**
  - *First ask why the query is parallel at all* — usually fixing the index makes the parallelism evaporate
  - Then tune workload-wide: cost threshold 25–50, MAXDOP = 8 or cores-per-NUMA-node
  - `CXCONSUMER` is benign — ignore it

### PLAN / QUERY REGRESSION
- **Tell:** "it was fine yesterday" · same query now slow · bimodal performance

**Diagnose — did a query regress / does it have multiple plans?**
```sql
select
    p.query_id, p.plan_id,
    rs.avg_duration / 1000.0 as avg_ms, rs.avg_cpu_time / 1000.0 as cpu_ms,
    rs.count_executions, p.is_forced_plan
from sys.query_store_plan as p
inner join sys.query_store_runtime_stats as rs on p.plan_id = rs.plan_id
where p.query_id = <id>
order by rs.avg_duration desc;
```

- **Causes:** parameter sniffing (multiple plans, divergent perf) · stale stats · CE version change after compat bump · plan eviction
- **Fix:**
  - Force the good plan (`sp_query_store_force_plan`)
  - Update stats, or address sniffing (`RECOMPILE` / `OPTIMIZE FOR`)
  - Use the SSMS Query Store "Regressed Queries" report

### NETWORK / CLIENT
- **Tell:** `ASYNC_NETWORK_IO` dominant
- **Causes:** almost always the **app**, not SQL — client consuming results row-by-row · no pagination · pulling huge result sets · slow network to client
- **Fix:**
  - App-side: paginate, consume results faster, return less data, fix the driver/ORM fetch pattern
  - Rarely a genuine network issue — SQL is healthy, don't tune the server

## EMERGENCY "BREAK GLASS" ACTIONS
Use deliberately — each has a cost.
```sql
-- Stop a runaway / blocker (rollback may be long; KILL <id> WITH STATUSONLY to watch progress)
kill <session_id>;

-- Bad plan from stale stats
update statistics dbo.YourTable with fullscan;

-- Pin a known-good plan
exec sp_query_store_force_plan @query_id = <id>, @plan_id = <id>;

-- Evict ONE bad plan (avoid clearing the whole cache in prod)
dbcc freeproccache (<plan_handle>);

-- Log can't truncate because DB isn't in full recovery (then take a log backup)
alter database [YourDB] set recovery full;
backup log [YourDB] to disk = N'...';   -- when log_reuse_wait_desc = 'LOG_BACKUP'
```

⚠ **Avoid in production unless you mean it:**
- `dbcc freeproccache` (no args) — clears the *entire* cache, mass recompiles
- `dbcc dropcleanbuffers` — dumps the buffer pool
- Killing a large write transaction — uninterruptible rollback

## THRESHOLD QUICK REFERENCE
| Metric | Healthy | Investigate | Bad |
|---|---|---|---|
| Data file read latency | < 10 ms | 10–20 ms | > 20–50 ms |
| Log file write latency | < 5 ms | 5–15 ms | > 15 ms |
| Signal wait % | < 10% | 15–20% | > 20% (CPU) |
| `runnable_tasks_count` | 0 | occasional spikes | sustained > 0 |
| Memory grants pending | 0 | — | > 0 sustained |
| Compilations ÷ batch req/sec | < 10% | 10–20% | > 20% |
| Blocking duration | < 1 s bursts | seconds | growing / unbounded |
| `log_reuse_wait_desc` | `NOTHING` | `LOG_BACKUP` | `ACTIVE_TRANSACTION` |

| Need | DMV / source |
|---|---|
| Live activity | `sys.dm_exec_requests` + `sys.dm_exec_sessions` |
| Waits (aggregate) | `sys.dm_os_wait_stats` |
| Live waits / blocking | `sys.dm_os_waiting_tasks` |
| CPU schedulers | `sys.dm_os_schedulers`, ring_buffer SCHEDULER_MONITOR |

| File I/O latency | `sys.dm_io_virtual_file_stats()` |
| Locks | `sys.dm_tran_locks` |
| Memory grants | `sys.dm_exec_query_memory_grants` |
| tempdb usage | `sys.dm_db_session_space_usage` |
| Index usage / missing | `sys.dm_db_index_usage_stats`, `sys.dm_db_missing_index_*` |
| Stats freshness | `sys.dm_db_stats_properties()` |
| Spinlocks | `sys.dm_os_spinlock_stats` |
| Plan regression | `sys.query_store_*` |
| Errors / deadlocks | `sys.sp_readerrorlog`, `system_health` XEvents |
