# SQL Server Alerting: Custom HTML Email Notifications from Agent Jobs

*Series 5 — DBA Operations | The SQL Server Deep Dive*

---

A SQL Server Agent job fails at 11 PM. The backup didn't run. The ETL missed its window. Nobody knows until someone checks the Job History the next morning — or until downstream systems start breaking.

SQL Server has had the ability to send email notifications for decades, and the majority of production environments still don't use it. Setting up Database Mail takes fifteen minutes. Wiring it to Agent jobs takes five more. The payoff is that failures show up in your inbox instead of waiting to be discovered.

This article covers how to set up Database Mail, build a stored procedure that sends structured HTML job-status notifications, and connect it to SQL Server Agent so the right people hear about failures immediately.

---

## Setting Up Database Mail

Database Mail is SQL Server's outbound email engine. Before you can send any notifications, it needs to be enabled and configured with at least one mail profile.

**Step 1: Enable Database Mail**

```sql
-- Enable the Database Mail XPs configuration option
EXEC sp_configure 'show advanced options', 1;
RECONFIGURE;

EXEC sp_configure 'Database Mail XPs', 1;
RECONFIGURE;
```

**Step 2: Create a Mail Account**

A mail account defines the SMTP server connection. This is where SQL Server connects to send messages.

```sql
EXEC msdb.dbo.sysmail_add_account_sp
    @account_name            = 'SQL Alerts Account',
    @description             = 'Account for SQL Server automated alerts',
    @email_address           = 'sqlserver@yourcompany.com',
    @display_name            = 'SQL Server Alerts',
    @mailserver_name         = 'smtp.yourcompany.com',
    @port                    = 587,
    @enable_ssl              = 1,
    @username                = 'sqlserver@yourcompany.com',
    @password                = 'your_smtp_password';
```

**Step 3: Create a Mail Profile**

A profile groups one or more accounts and is the named entity your code references when sending mail.

```sql
EXEC msdb.dbo.sysmail_add_profile_sp
    @profile_name = 'SQL Alerts',
    @description  = 'Profile for automated SQL Server notifications';

EXEC msdb.dbo.sysmail_add_profileaccount_sp
    @profile_name   = 'SQL Alerts',
    @account_name   = 'SQL Alerts Account',
    @sequence_number = 1;
```

**Test the setup:**

```sql
EXEC msdb.dbo.sp_send_dbmail
    @profile_name = 'SQL Alerts',
    @recipients   = 'dba-team@yourcompany.com',
    @subject      = 'Database Mail Test',
    @body         = 'If you received this, Database Mail is working.';
```

## Building the Job Status Notification Procedure

Once Database Mail is working, the useful step is building a procedure that queries the Agent job history, formats the results into an HTML table, and sends it as a readable report.

```sql
CREATE OR ALTER PROCEDURE dbo.usp_SendJobStatusEmail
    @JobName    NVARCHAR(128),
    @Recipients NVARCHAR(500) = 'dba-team@yourcompany.com'
AS
BEGIN
    SET NOCOUNT ON;

    DECLARE @JobId      UNIQUEIDENTIFIER;
    DECLARE @RunStatus  INT;
    DECLARE @RunDate    INT;
    DECLARE @RunTime    INT;
    DECLARE @Duration   INT;
    DECLARE @Message    NVARCHAR(4000);
    DECLARE @Subject    NVARCHAR(500);
    DECLARE @Body       NVARCHAR(MAX);

    -- Get the most recent job run details from msdb
    SELECT TOP 1
        @JobId     = j.job_id,
        @RunStatus = jh.run_status,
        @RunDate   = jh.run_date,
        @RunTime   = jh.run_time,
        @Duration  = jh.run_duration,
        @Message   = jh.message
    FROM msdb.dbo.sysjobs AS j
    INNER JOIN msdb.dbo.sysjobhistory AS jh
        ON j.job_id = jh.job_id
    WHERE j.name = @JobName
      AND jh.step_id = 0  -- 0 = the job outcome row (not individual steps)
    ORDER BY jh.run_date DESC, jh.run_time DESC;

    IF @JobId IS NULL
    BEGIN
        RAISERROR('Job "%s" not found in msdb.', 16, 1, @JobName);
        RETURN;
    END

    -- Build the subject line based on outcome
    SET @Subject = CASE @RunStatus
        WHEN 1 THEN '[SQL Server] SUCCESS: ' + @JobName
        WHEN 0 THEN '[SQL Server] FAILED: ' + @JobName
        WHEN 3 THEN '[SQL Server] CANCELLED: ' + @JobName
        ELSE         '[SQL Server] UNKNOWN STATUS: ' + @JobName
    END;

    -- Format run date and time from SQL Agent's integer format
    DECLARE @RunDateFormatted VARCHAR(20) =
        STUFF(STUFF(CAST(@RunDate AS VARCHAR(8)), 5, 0, '-'), 8, 0, '-');

    DECLARE @RunTimeFormatted VARCHAR(20) =
        RIGHT('000000' + CAST(@RunTime AS VARCHAR(6)), 6);
    SET @RunTimeFormatted =
        LEFT(@RunTimeFormatted, 2) + ':' +
        SUBSTRING(@RunTimeFormatted, 3, 2) + ':' +
        RIGHT(@RunTimeFormatted, 2);

    -- Duration in seconds
    DECLARE @DurationSeconds INT =
        (@Duration / 10000) * 3600 +
        ((@Duration % 10000) / 100) * 60 +
        (@Duration % 100);

    -- Build HTML email body
    SET @Body = N'
<html><body>
<h2 style="color:' + CASE @RunStatus WHEN 1 THEN '#2e7d32' ELSE '#c62828' END + ';">' +
    CASE @RunStatus WHEN 1 THEN '✓ Job Succeeded' ELSE '✗ Job Failed' END +
'</h2>
<table border="1" cellpadding="5" cellspacing="0" style="border-collapse:collapse; font-family:Arial; font-size:13px;">
  <tr style="background:#f5f5f5;"><td><b>Job Name</b></td><td>' + @JobName + '</td></tr>
  <tr><td><b>Run Date</b></td><td>' + @RunDateFormatted + '</td></tr>
  <tr><td><b>Run Time</b></td><td>' + @RunTimeFormatted + '</td></tr>
  <tr style="background:#f5f5f5;"><td><b>Duration (sec)</b></td><td>' + CAST(@DurationSeconds AS VARCHAR) + '</td></tr>
  <tr><td><b>Status</b></td><td>' +
    CASE @RunStatus
        WHEN 1 THEN 'Succeeded'
        WHEN 0 THEN 'Failed'
        WHEN 3 THEN 'Cancelled'
        ELSE 'Unknown'
    END +
  '</td></tr>
  <tr style="background:#f5f5f5;"><td><b>Message</b></td><td>' + ISNULL(@Message, 'No message') + '</td></tr>
</table>
<p style="color:#777; font-size:11px;">Sent automatically by SQL Server on ' + @@SERVERNAME + '</p>
</body></html>';

    -- Send the email
    EXEC msdb.dbo.sp_send_dbmail
        @profile_name  = 'SQL Alerts',
        @recipients    = @Recipients,
        @subject       = @Subject,
        @body          = @Body,
        @body_format   = 'HTML';
END;
```

The procedure reads `msdb.dbo.sysjobhistory`, formats the outcome into an HTML table with green/red headers based on success or failure, and sends it through the `SQL Alerts` profile.

## Wiring Notifications to Agent Jobs

Once the procedure exists, add a final step to any Agent job that should send notifications:

```sql
-- Add notification step to an existing job
EXEC msdb.dbo.sp_add_jobstep
    @job_name      = 'Nightly ETL',
    @step_name     = 'Send Status Email',
    @command       = N'EXEC dbo.usp_SendJobStatusEmail @JobName = N''Nightly ETL'';',
    @on_success_action = 1,  -- Quit with success
    @on_fail_action    = 1;  -- Quit with success (email sent regardless)
```

Setting `@on_fail_action = 1` on the notification step ensures the email goes out even when a previous step failed — otherwise SQL Agent stops executing steps on failure and the notification never fires.

Alternatively, configure notifications through the Agent job's built-in notification UI:

```sql
-- Configure job to send email on failure via Agent Operator
EXEC msdb.dbo.sp_update_job
    @job_name        = 'Nightly ETL',
    @notify_email_operator_name = 'DBA Team',
    @notify_level_email = 2;  -- 2 = on failure
```

This requires an Operator configured in SQL Server Agent with the team's email address.

## Monitoring the Mail Queue

Database Mail is asynchronous — messages go into a queue and are sent by a background Service Broker service. If emails aren't arriving, check the queue:

```sql
-- Check sent mail log
SELECT TOP 20
    send_request_date,
    sent_date,
    recipients,
    subject,
    sent_status,
    sent_account_id
FROM msdb.dbo.sysmail_allitems
ORDER BY send_request_date DESC;

-- Check for failed mail
SELECT *
FROM msdb.dbo.sysmail_faileditems
ORDER BY send_request_date DESC;
```

`sent_status` values: `sent`, `failed`, `unsent`. Failed items usually indicate SMTP authentication or connection issues. The `description` column on failed items shows the error detail.

## The Trap

**Sending emails only on failure.** It feels right — you don't want noise when things work. But silence is indistinguishable from "the notification step didn't fire." If you never receive success notifications, you can't tell whether the job succeeded quietly or whether the notification mechanism itself broke.

A practical pattern: send success notifications for critical jobs (nightly ETL, backup jobs, index maintenance) with a low-verbosity HTML summary. For less critical jobs, use Agent's built-in failure-only notification. This way:

- Critical job succeeds → you get a one-line success email
- Critical job fails → you get a detailed failure email
- Notification mechanism fails → you notice the absence of expected success emails

Also: test your mail setup regularly. Database Mail profiles can stop working due to SMTP password rotation, certificate changes, or service restarts. Don't discover the mail is broken at the same time you're trying to diagnose an incident.

## Key Takeaways

- **Database Mail requires `Database Mail XPs` enabled** — configure one account (SMTP server) and one profile (named reference used in code); test immediately after setup
- **`sp_send_dbmail` with `@body_format = 'HTML'`** — send structured HTML tables rather than plain text for readable notifications; color-code by success/failure
- **`msdb.dbo.sysjobhistory` is the source of truth for job outcomes** — query it with `step_id = 0` for the job-level result, not individual steps
- **Add notification steps with `@on_fail_action = 1`** — the notification step must succeed regardless of prior step outcomes; otherwise failures suppress the notification
- **Check `sysmail_faileditems` when email stops arriving** — SMTP configuration problems surface here with error details
- **Send success notifications for critical jobs** — absence of expected success email is an early warning that the notification pipeline itself is broken
